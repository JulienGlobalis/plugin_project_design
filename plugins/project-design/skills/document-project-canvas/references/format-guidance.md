# Project Canvas Format Guidance

## Native Markdown

- Use one H1 title and H2 headings for the ten required sections.
- Use H3 headings for stable subsections.
- Use standard Markdown tables only when their width remains readable.
- Prefer lists or repeated short subsections when a table would become too
  wide.
- Keep local or source links intact when they are valid for the delivery
  context.
- Check heading order, table delimiters, local links, and code-fence balance.

Markdown is the default when the user does not request another format.

## Microsoft Word

- Produce a real `.docx` file with semantic title, heading, paragraph, list,
  and table styles.
- Use a supplied compatible Word template when requested; preserve its page
  size, margins, headers, footers, approved styles, and branding unless the
  user requests a change.
- Without a template, use a restrained professional layout with readable
  typography, consistent spacing, accessible contrast, and page numbers when
  the document spans multiple pages.
- Repeat table header rows where supported and avoid unreadable column widths.
- Avoid orphaned headings and prevent important register rows from becoming
  visually ambiguous across page breaks.
- Render the document to pages and inspect every page for clipping, overlap,
  blank pages, broken tables, inconsistent headings, and footer collisions.

Do not claim Word delivery until the `.docx` opens and the rendered result has
been inspected.

## Google Docs

- Produce or update a native Google Docs document, not an uploaded plain-text
  substitute.
- Use native title, heading, paragraph, list, and table structures.
- Apply a supplied compatible Google Docs template when requested, preserving
  its supported layout and branding without carrying stale project facts.
- Without a template, use the same restrained hierarchy as the native
  Markdown structure.
- Preserve document accessibility and avoid color-only status encoding.
- Read back the document after writing to verify section order, table content,
  links, and material text. Inspect the visible result when available.

Do not claim Google Docs delivery until the native document exists and its
content has been verified.

## Template Compatibility

A template is compatible only when it can represent all required Canvas
sections and all material statuses, contradictions, questions, readiness, and
traceability without deleting, merging, or inventing content.

If a template omits a required role, extend it consistently when authorized.
If protected controls, fixed topology, or user instructions forbid the needed
extension, stop and report the incompatibility rather than dropping content.
