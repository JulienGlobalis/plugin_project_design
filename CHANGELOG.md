# Changelog

All notable changes to this project are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and the project uses [Semantic Versioning](https://semver.org/). Each released
version matches a Git tag `vX.Y.Z`. The plugin release version is distinct
from the methodology version of each skill.

## [Unreleased]

## [0.1.0] - 2026-09-29

First tagged release. It gathers every change since the initial scaffolding of
2026-07-23.

### Added

- Added the initial plugin structure.
- Added the Codex manifest.
- Added the Claude Code manifest.
- Added the initial orchestration and specialized skill scaffolding.
- Added shared-resource placeholders and conventions.
- Added Spec Kit integration placeholders and architectural boundaries.
- Added root `AGENTS.md` and `CLAUDE.md` entry points that direct Codex and
  Claude to the single continuity source in `development/PROJECT_CONTEXT.md`.
- Defined the boundary between development examples and approved skill
  references used at runtime.
- Added a cross-conversation project context and simplified manual tests to
  one Markdown file per skill.
- Implemented `project-framing` methodology version 0.1 with proportionate
  questioning, uncertainty-aware framing, lifecycle separation, traceable
  outputs, four fixture validations, and a real-project manual test workbook.
- Added the initial French terminology companion for all canonical concepts,
  shared-model labels, and localization fallback rules.
- Defined version 0.1 of the Minimal Normalized Project Model with shared
  elements, relationships, normalization status, lifecycle perspective, and
  Knowledge Model traceability.
- Defined version 0.1 of the Minimal Knowledge Model for assertions,
  provenance, epistemic state, contradiction, coexistence, and traceability.
- Defined version 0.1 of the corpus-driven Canonical Domain Model with 22
  shared concepts and explicit exclusions.
- Accepted the layered Source Documents, Knowledge Model, Project Model, and
  Generated Artefacts information architecture.
- Added golden-output governance, regression classification, release
  validation, and execution-history conventions.
- Added repository-wide and skill-specific quality checklists.
- Added shared scenarios for Codex and Claude Code.
- Added four fictional, fully anonymized, multi-artefact permanent regression
  fixtures representing realistic consulting inputs.
- Added the documentation-first testing strategy.
- Documented the separation between design skills and future
  document-specific restitution skills.
- Added runtime Project Canvas guidance and a short fictional structural
  example, including readiness and traceable later-adjustment rules.
- Extended fixture scenarios, quality criteria, and the manual replay to test
  `project-framing` and `document-project-canvas` sequentially.
- Implemented `document-project-canvas` methodology version 0.1 for verified
  native Markdown, Microsoft Word, and Google Docs restitution from a
  validated Project Canvas without changing business knowledge.
- Defined Shared Document Model version 0.1 as the discipline-neutral contract
  for business artefacts, documents, formats, templates, traceability, and all
  current or future document skills.
- Added the official Plugin Architecture Overview v1.0 and a complete
  coherence review of models, skills, artefact ownership, document ownership,
  flows, dependencies, boundaries, and roadmap readiness.
- Added the `_project-design/` target-project workspace convention for all
  durable Markdown artefacts and documents generated by the plugin.
- Added a concise pre-execution brief for every skill covering the selected
  capability, inputs, generated deliverables, and user-supplied models or
  templates.
- Implemented the guided `project-design` entry with explicit consent, safe
  idempotent `_project-design/` initialization, default `project-framing`
  selection, documentary-output choice, and specialized-skill handoff.
- Added `_project-design/project-design-state.json` for non-business control
  state only, with atomic updates and no project, source, question, answer, or
  Canvas content.
- Added explicit framing-iteration preparation, pending-answer,
  question-batch closure, and iteration-completion phases so existing Canvas
  questions resume safely across conversations, partial answers and explicit
  deferrals remain distinct, and every necessary question can be presented
  without an arbitrary numeric cap.
- Added runtime structure, quality checklist, fictional example, automated
  contract checks, all-four-fixture observations, and a manual creation/update
  replay without changing Golden Outputs.
- Added stable identifiers, change-history rules, actors and roles, global
  Processes, the product-module-feature inventory, detailed feature
  specifications, interfaces and fields, Business Rules, acceptance criteria,
  and a single global message catalog.
- Implemented `functional-design` methodology version 0.1 for creation,
  review, and controlled evolution of a living Functional Design artefact.
- Added a project-manager interaction contract for grounded recommendations,
  decision consequences, progressive answers, reuse of explicit setup choices,
  reviewable approval, and an actionable direct functional-design handoff.

### Changed

- Expanded the cross-conversation context with the prompt history, future
  roadmap, deferred decisions, and runtime-example policy.
- Made runtime quality contracts self-contained so the installed plugin no
  longer depends on fixtures or development checklists.
- Isolated the installable plugin under `plugins/project-design/`, moved
  versioned development resources under `development/`, added an ignored
  `.local/` workspace, and added a repository marketplace entry.
- Updated the four fixture scenarios, quality contracts, and manual tests for
  Project Canvas validation without changing Golden Outputs.
- Recorded the earlier generic documentary-orchestrator option, now
  superseded by the discipline-specific architecture.
- Repositioned `project-framing` as the first project-design step and made a
  ten-section Project Canvas its primary Markdown artefact.
- Audited and clarified the documented skill architecture, installed versus
  future capability status, design-versus-restitution boundary, and separate
  documentary roadmap before the definitive discipline-specific decision.
- Replaced the former generic documentary-orchestration placeholder with four
  discipline-specific document-skill placeholders and made the
  business-artefact/document boundary definitive.
- Made `project-framing` present the ten Canvas chapters, accept a project
  description or sources, and co-construct the Canvas through focused
  question-and-answer rounds before optional Word or Google Docs restitution.
- Advanced guided-entry/framing/functional methodology revisions to 0.5/0.6/0.2;
  plugin release versions and installed copies are unchanged.
- Distinguished active and explicitly deferred Canvas questions on resumption
  and corrected a conflicting reference that made saved readiness optional.
- Rewrote the root README in French on the Globalis marketplace model:
  installation-first layout, corrected Codex and Claude Code install and
  update commands, skill table, example prompts, and maintainer checks.
- Moved the primary Git remote to
  `git@gitlab.com:globalis-ms/marketplace/llm_plugin_project_design.git`.
- Restructured this changelog on the Keep a Changelog format.

### Fixed

- Reject invalid Word packages before recording completed delivery; retain
  native rendering and semantic verification as separate required checks.
