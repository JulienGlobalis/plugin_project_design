# Technical Design Checklist

## Current Contract

- [ ] Architecture context and technical concerns trace to the Project Canvas
      and validated project or functional Needs.
- [ ] Existing state, constraints, proposals, and approved decisions remain
      distinct.
- [ ] Technologies, components, Integrations, APIs, flows, security,
      performance, deployment, Risks, and non-functional Requirements are not
      invented.
- [ ] Technology choices are supported by evidence and decision status.
- [ ] Migration, continuity, security, data, and operational uncertainty remain
      visible when relevant.
- [ ] The output does not implement runtime code.
- [ ] Founded Canvas adjustments are identified for traceable review rather
      than silently applied.
- [ ] The skill remains independently callable and Spec Kit independent.
