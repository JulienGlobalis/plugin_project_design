# Project Framing

## Status

UNDER CONSTRUCTION

The detailed framing methodology and output templates are TO BE DEFINED.

## Purpose

Eventually establish a clear, traceable foundation for an application or software project before downstream design work.

## Expected Inputs

- A project idea, brief, existing documentation, or discovery notes.
- Known business context, objectives, stakeholders, constraints, and uncertainties.

## Expected Outputs

- A structured project-framing artefact.
- Explicit objectives, scope, stakeholders, constraints, risks, assumptions, and open questions.

Output structures are TO BE DEFINED.

## Boundaries

- Remain independently callable without the `project-design` orchestrator.
- Remain fully usable without GitHub Spec Kit.
- Do not define functional requirements, technical architecture, backlog items, or detailed methodology in this iteration.
- Do not turn assumptions into facts.
