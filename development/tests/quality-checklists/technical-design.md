# Technical Design Checklist

## Current Contract

- [ ] Architecture context and technical concerns trace to validated project or
      functional needs.
- [ ] Existing state, constraints, proposals, and approved decisions remain
      distinct.
- [ ] Components, flows, integrations, risks, and non-functional requirements
      are not invented.
- [ ] Technology choices are supported by evidence and decision status.
- [ ] Migration, continuity, security, data, and operational uncertainty remain
      visible when relevant.
- [ ] The output does not implement runtime code.
- [ ] The skill remains independently callable and Spec Kit independent.
